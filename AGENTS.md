# Repository instructions

These instructions apply to the entire repository.

## Automatic commits

- After completing a requested change and passing the relevant checks, create a Git commit automatically. The user has authorized this; do not ask for confirmation each time.
- Stage only changes belonging to the completed task. Preserve unrelated user changes.
- Use a clear, concise English commit message describing the completed change.
- Do not commit secrets, local settings, dependencies, caches, logs, generated builds, or packaged release binaries. Keep the appropriate ignore rules in place.
- If the work is incomplete or checks fail, explain the remaining issue rather than committing it as finished.
- Report the commit hash and verification results when handing the work back.
- Push commits or publish releases only when the user requests it.
